# Rulet.tv Voice Assistant

Отдельное расширение для видеочата rulet.tv (страница приложения сейчас называется Camble). Оно слушает входящий звук видеочата, передаёт его локальному серверу для распознавания и ответа, а сгенерированную речь отправляет собеседнику и, по настройке, проигрывает через аудиовыход ПК.

Расширение не начинает звонки, не выбирает собеседников и не нажимает кнопки сайта. Текст роли и манера речи задаются в `server/system_prompt.txt`; проверьте их до использования.

## Как устроено

```text
rulet.tv WebRTC -> расширение -> локальный Python-сервер
                                      STT -> YandexGPT -> SpeechKit TTS
rulet.tv WebRTC <- PCM для собеседника <-┘
динамики ПК     <- тот же PCM-поток   <-┘
```

Расширение запускается только на `rulet.tv` и его поддоменах. Оно использует стандартные WebRTC API страницы, захватывает только входящую речь собеседника и подменяет исходящий аудиотрек голосом ИИ. Физический звук микрофона не отправляется, но сайт должен получить разрешение на микрофон, чтобы создать исходящий аудиотрек. Видео не изменяется.

Проверка страницы подтвердила, что загруженный клиентский код использует `RTCPeerConnection` и `getUserMedia`. Полный видеозвонок здесь не запускался: в браузере проверки нет камеры и микрофона. Перед обычным использованием протестируйте с согласным собеседником.

## Требования

- Windows и Chrome, Яндекс Браузер или Edge на базе Chromium 116+.
- Python 3.11+.
- Аккаунт Yandex Cloud с ключом для SpeechKit и YandexGPT.
- Рабочие камера и микрофон, если этого требует настройка видеочата.

## Установка сервера

В PowerShell откройте папку `server` и выполните:

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
copy .env.example .env
notepad .env
```

В `.env` укажите `YC_API_KEY` и `YC_FOLDER_ID`, сохраните файл и запустите сервер:

```powershell
python main.py
```

Ключи храните только на своём ПК, не отправляйте их в чат и не помещайте в расширение. До подключения расширения добавьте его ID в `server/config.yaml` (инструкция ниже): пустой список разрешённых ID намеренно закрывает WebSocket. Проверить сервер можно по адресу <http://127.0.0.1:8765/health>.

## Установка расширения

1. Распакуйте архив.
2. Откройте `chrome://extensions` (в Яндекс Браузере — `browser://extensions`) и включите режим разработчика.
3. Нажмите «Загрузить распакованное расширение» и выберите вложенную папку `extension`.
4. Скопируйте ID расширения, показанный на этой странице.
5. В `server/config.yaml` укажите его в `server.allowed_extension_ids`, например `allowed_extension_ids: ["вставьте-ID-сюда"]`, затем перезапустите сервер. Не оставляйте в файле слово-заполнитель.
6. Откройте боковую панель нажатием на значок расширения, затем нажмите **Настройки**.
7. Укажите адрес сервера `ws://127.0.0.1:8765/ws`, при необходимости токен, и выберите режим.
8. Включите автоответчик, обновите вкладку rulet.tv и разрешите камеру/микрофон, если браузер запросит доступ. Начинайте видеочат вручную.

Флажок «Проигрывать ответ через динамики ПК» включён по умолчанию. Это тот же синтезированный аудиопоток, который отправляется собеседнику; второго запроса к SpeechKit нет. Браузеру может понадобиться щелчок по странице, чтобы разрешить воспроизведение.

## Настройки и проверка

В настройках доступны включение/выключение, режим «Отвечать голосом» или «Только слушать», вывод через динамики, адрес сервера, токен, приветствие и паузы. Смена адреса или токена переподключает сервер. По умолчанию используется приветствие `Привет, я Марина`, задержка появления видео 1000 мс, пауза тишины 800 мс и дополнительная пауза ответа 300 мс.

Боковая панель показывает местное время каждой реплики и задержку от распознанного вопроса до первого аудиофрагмента ответа. Ссылка **rulet.tv** в заголовке панели открывает сайт в новой вкладке. Кнопка **«Копировать для отладки»** включает версии, браузер, настройки, состояние подключения и текст разговора; проверьте текст перед пересылкой. Токен не включается в отчёт. Отладочные записи расширения хранятся только в памяти до закрытия service worker; старые сохранённые логи удаляются при обновлении.

- Режим «Только слушать» распознаёт входящую речь, но не подменяет исходящий голос.
- При «Отвечать голосом» исходящий аудиотрек заменяется голосом ИИ. Если выключить микрофонную кнопку на сайте, голос автоответчика тоже может перестать передаваться.
- Чтобы не отвечать незнакомым людям, выключите автоответчик в настройках до начала нужного разговора.
- Чтобы проверить работу, используйте видеочат с человеком, который согласен на тест. Этот проект не выполняет автоматическое сопоставление и не нажимает «Начать» или «Пропустить».
- В консоли страницы появятся сообщения с префиксом `[RuletTV]`. Для быстрой диагностики доступны `__RUTV_DEBUG__.state()` и `__RUTV_DEBUG__.beep()`.
- При смене удалённого видеотрека текущий диалог завершается, чтобы контекст предыдущего собеседника не переходил к следующему. После потери видео расширение ждёт 1,2 секунды перед сбросом; затем новый разговор начнётся после минимум 3 секунд стабильного видео.
- После обновления расширения перезагрузите вкладку rulet.tv.

Если сайт показывает `Requested device not found`, проверьте подключение и разрешения камеры/микрофона в настройках браузера. Если в консоли нет `[RuletTV] перехватчик WebRTC активен`, обновите вкладку и убедитесь, что расширение разрешено для `rulet.tv`.

## Голос и безопасность

В `server/config.yaml` по умолчанию используется голос SpeechKit `alena`; его можно изменить на другой доступный голос. Голоса с точным именем `alice` в SpeechKit нет.

Оставьте `server.allow_any_origin` выключенным: его включение отключает проверку списка ID расширений.

`server/system_prompt.txt` задаёт голос помощника от первого лица и содержит пользовательские сведения; прочитайте и отредактируйте его перед запуском. По инструкции модели просьба прекратить разговор или сообщение о возрасте младше 18 лет завершается специальным маркером, после которого текущая сессия останавливается. Это зависит от того, распознает ли модель такую просьбу и вернёт ли маркер. Распознанный текст не записывается расширением в постоянное хранилище или сервером в журнал. Аудио обрабатывается сервисами Яндекса и не записывается сервером на диск.
