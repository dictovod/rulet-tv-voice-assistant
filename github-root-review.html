Корневые файлы GitHub: что обновлять

Проверено 7 октября 2026 · ветка main и опубликованные файлы репозитория

Обновлять нужно проверяющий скрипт и встроенную в HTML-инструкцию копию. README уже описывает 0.4.6, а правила в `.gitignore` подходят, но в Git уже отслеживается `server/.env`, поэтому одних правил игнорирования недостаточно для защиты будущих ключей.

Главный риск. Опубликованный `server/.env` сейчас содержит только заглушки, не настоящие ключи. Но Git продолжит отслеживать этот файл даже при наличии правила `server/.env` в `.gitignore`. Если заменить заглушки реальными значениями и закоммитить изменения, ключи могут попасть в репозиторий.

Что подтверждено

  • На GitHub в `server/.env` найдены только значения-заглушки; действительных ключей в опубликованных значениях не обнаружено.
  • В `server/config.yaml` ссылки на `${YC_API_KEY}` и `${YC_FOLDER_ID}`, реальных учётных значений не найдено.
  • `server/system_prompt.txt` содержит личные сведения и уже опубликован. Это отдельный вопрос приватности, не проблема корневых файлов.
  • Страница Mail.ru показывает файл `rulet-tv-voice-assistant-fixed.zip`, но не показывает его версию. По открытому листингу нельзя подтвердить, что это сборка 0.4.6.

Итог

README и `.gitignore` не требуют переписывания. Проверяющий скрипт и HTML-инструкцию стоит обновить вместе. Для безопасной работы с ключами нужно убрать уже отслеживаемый `.env` из Git и использовать локальный `.env`, создаваемый из `.env.example`.
